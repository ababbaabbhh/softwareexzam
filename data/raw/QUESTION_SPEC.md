# 题库 JSON 规范（生成子任务必读）

## 文件格式

每个文件是一个 JSON 对象，UTF-8，无 BOM、无注释、无 Markdown 代码围栏：

```json
{ "questions": [ ... ] }
```

## 通用字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| type | 是 | `single` 单选 / `multi` 多选 / `fill` 填空 / `tf` 判断 / `subjective` 主观 |
| topic | 是 | 模块代码，见下表，必须严格使用代码本身 |
| knowledge | 是 | 具体考点，10 字以内，如"二叉树遍历""PV 操作""第三范式" |
| difficulty | 是 | 1=易 2=中 3=难 |
| stem | 是 | 题干（中文，严谨、无歧义） |
| options | 除 tf/subjective 外必填 | 数组，选项文本**不带** "A." 前缀 |
| answer | 是 | 见下 |
| explanation | 客观题必填 | 解析，说明正确理由与干扰项错因，80–200 字 |
| rubric | 主观题必填 | 评分要点数组 |
| score | 主观题必填 | 满分（下午卷 15） |

## 各题型细则

### single（单选）
- options 恰好 4 项，answer 为 1 个字母的数组，如 `["B"]`。
- 四个选项互斥，只有一个正确；干扰项要像真题（易混淆概念、计算陷阱）。

### multi（多选）
- options 4–5 项，answer 至少 2 个字母，升序，如 `["A","C"]`，不得全选。

### tf（判断）
- 无 options。answer 为 `["对"]` 或 `["错"]`。
- stem 是一句可判断真伪的陈述句，不要出现"下列说法正确的是"。

### fill（填空）
- stem 中每个空用 4 个下划线 `____` 表示；空数 = answer 数组长度。
- 每个答案可含多个可接受写法，用 `|` 分隔，如 `["O(nlogn)|O(n log n)"]`。
- 答案尽量短（词/数字/术语），便于机器判分。

### subjective（主观）
- stem：完整案例描述 + 若干小问（问题1、问题2……）。
- answer：标准答案全文（含各小问答案）。
- rubric：评分要点数组，每项如 "答出外部实体'客户'得 2 分"。
- score：满分（下午卷 15 分）。
- 必须包含可核对的标准答案，便于用户自评。

## 模块代码

| 代码 | 模块 |
| --- | --- |
| DS_ALGO | 数据结构与算法 |
| SE | 软件工程（含项目管理、软件文档） |
| OO | 面向对象技术（UML、设计模式、面向对象程序设计） |
| DB | 数据库系统 |
| OS | 操作系统 |
| NET | 计算机网络 |
| PL | 程序设计语言与编译原理 |
| CO | 计算机组成与体系结构 |
| SEC | 信息安全与法律法规 |
| MULTI | 多媒体技术 |

## 质量红线

1. 原创命题，禁止大段照搬某套真题原文。
2. 题干中文；技术术语可用英文缩写。
3. 同一文件内考点分散：相邻 3 题不得同属同一考点。
4. 难度大致 易:中:难 = 2:5:3。
5. 计算题必须算得通：进制、子网、流水线、Cache 命中率、哈夫曼、复杂度等数值自洽。
6. 主观题标准答案要分点作答，可直接对照自评。
