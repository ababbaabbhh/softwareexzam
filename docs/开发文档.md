## 1. 项目概述

### 1.1 背景

用户备考软考中级「软件设计师」，需要一个本地化、可离线、可在局域网与手机浏览器访问的**模拟考试系统**，用于检验复习效果。

### 1.2 目标

| 编号 | 目标 | 验收标准 |
| --- | --- | --- |
| G1 | 题库丰富且覆盖全部考点 | 单选+多选 ≥ 1000；填空+判断 ≥ 500；主观题 ≥ 200；覆盖 11 个知识模块 |
| G2 | 全真模拟考试流程 | 倒计时、答题卡、未答拦截交卷、到点强制交卷、自动评分 |
| G3 | 试卷结构贴近真题 | 上午卷 75 题单选 / 150 分钟 / 75 分；下午卷 5 道案例 / 150 分钟 / 75 分 |
| G4 | 考点分散、随机组卷 | 按考点权重分层随机抽题，每次试卷不同，同一模块占比受控 |
| G5 | 主观题阅卷辅助 | 交卷后展示标准答案与评分要点，支持按评分点自评得分 |
| G6 | 历史记录 | 可回看每次考试的得分、答题详情、主观题得分 |
| G7 | 单人使用、局域网访问、手机兼容 | 监听 0.0.0.0，提供局域网地址；响应式布局适配手机 |

### 1.3 非目标（本期不做）

- 多用户注册 / 登录 / 权限体系（单用户，局域网内共用）。
- 在线题库编辑器（题库通过 JSON 文件导入）。
- 主观题自动语义评分（改为标准答案 + 评分要点 + 人工自评）。
- 云端部署、HTTPS 证书。

## 2. 考试形式调研结论

### 2.1 官方考试结构

软件设计师属于软考中级，考试分两个科目，**两科均需达到 45 分（满分 75）才算通过**，单科成绩不保留。

#### 上午卷：基础知识

| 项目 | 内容 |
| --- | --- |
| 题型 | 75 道单项选择题 |
| 分值 | 每题 1 分，满分 75 分 |
| 时长 | 150 分钟（机考改革后为两科连考 240 分钟，上午科目最长 120 分钟、最短 90 分钟） |
| 合格线 | 45 分 |

#### 下午卷：应用技术

| 题号 | 题型 | 分值 | 说明 |
| --- | --- | --- | --- |
| 试题 1 | 数据流图（DFD）补全 | 15 分 | 外部实体、数据存储、数据流、父子图平衡 |
| 试题 2 | 数据库设计 | 15 分 | E-R 图转关系模式、主键/外键、SQL、范式 |
| 试题 3 | UML 建模 | 15 分 | 用例图、类图、状态图、活动图、时序图 |
| 试题 4 | 算法设计（C 语言/伪代码） | 15 分 | 补全代码、时间复杂度、算法思想 |
| 试题 5 | 面向对象程序设计（C++ / Java 二选一） | 15 分 | 设计模式 + 代码填空 |
| 合计 | 5 道 | 75 分 | 150 分钟，45 分合格 |

### 2.2 上午卷知识点分值分布（组卷权重依据）

| 模块 | 代码 | 真题占比 | 上午卷抽题数（共 75） |
| --- | --- | --- | --- |
| 数据结构与算法 | DS_ALGO | ~20% | 17 |
| 软件工程 | SE | ~19% | 14 |
| 面向对象技术（UML/设计模式） | OO | ~15% | 11 |
| 数据库系统 | DB | ~13% | 10 |
| 操作系统 | OS | ~11% | 8 |
| 计算机网络 | NET | ~8% | 6 |
| 程序设计语言与编译原理 | PL | ~7% | 5 |
| 计算机组成与体系结构 | CO | ~3% | 2 |
| 信息安全与法律法规 | SEC | ~2% | 1 |
| 多媒体技术 | MULTI | ~2% | 1 |
| **合计** | | 100% | **75** |

> 说明：真题中另有 5 道专业英语题（约 5 分），本题库以中文技术题替代，不单列英语模块。

### 2.3 参考来源

- 51CTO 软考《软件设计师到底考什么？》：两科连考 240 分钟、75 题单选、6 道案例题（新版机考）
- 林岑笔记《软考-软件设计师 考试结构与重点》：75 题单选 / 150 分钟 / 75 分 / 45 分合格，下午 5 道案例题
- 希赛、51CTO 历年真题结构（2017 改革后题型稳定）：上午 75 单选，下午 5 大题（第 5 题 C++/Java 二选一）

**本系统采用**：上午卷 = 75 单选 × 1 分；下午卷 = 5 大题 × 15 分（第 5 题在 C++/Java 中随机二选一）。

## 5. 数据库设计

### 5.1 表结构

```sql
-- 题库
CREATE TABLE questions (
  id          INTEGER PRIMARY KEY,
  ext_id      TEXT UNIQUE,        -- 导入时的稳定 ID（文件名#序号）
  type        TEXT NOT NULL,      -- single | multi | fill | tf | subjective
  topic       TEXT NOT NULL,      -- 知识模块代码（见 6.1）
  knowledge   TEXT,               -- 具体考点
  difficulty  INTEGER DEFAULT 2,  -- 1 易 / 2 中 / 3 难
  stem        TEXT NOT NULL,
  options     TEXT,               -- JSON 数组，如 ["...","..."]；主观/判断为空
  answer      TEXT NOT NULL,      -- JSON：["A"]；填空 ["答案1","答案2"]；判断 ["对"]；主观为标准答案文本 JSON 字符串
  rubric      TEXT,               -- 主观题评分要点，JSON 数组
  explanation TEXT,
  score       REAL NOT NULL DEFAULT 1
);

-- 试卷
CREATE TABLE exams (
  id              INTEGER PRIMARY KEY,
  mode            TEXT NOT NULL,      -- morning | afternoon | mixed
  title           TEXT,
  duration_sec    INTEGER NOT NULL,
  started_at      INTEGER NOT NULL,   -- 毫秒时间戳
  deadline_at     INTEGER NOT NULL,
  submitted_at    INTEGER,
  status          TEXT NOT NULL DEFAULT 'in_progress', -- in_progress | submitted | aborted
  auto_submitted  INTEGER DEFAULT 0,
  objective_score REAL,
  subjective_score REAL,
  total_score     REAL,
  max_score       REAL
);

-- 试卷题目与作答
CREATE TABLE exam_questions (
  exam_id     INTEGER NOT NULL,
  seq         INTEGER NOT NULL,       -- 题号，从 1 开始
  qid         INTEGER NOT NULL,
  section     TEXT NOT NULL,          -- 所属部分（如 上午卷 / 试题一 数据流图）
  score       REAL NOT NULL,
  user_answer TEXT,                   -- JSON，未作答为 NULL
  is_correct  INTEGER,                -- 客观题判分结果，主观题为 NULL
  awarded     REAL,                   -- 得分
  graded      INTEGER DEFAULT 0,      -- 主观题是否已自评
  PRIMARY KEY (exam_id, seq)
);

-- 键值设置（预留：当前活跃考试 ID 等）
CREATE TABLE settings (k TEXT PRIMARY KEY, v TEXT);
```

### 5.2 设计说明

- **ext_id 唯一约束** 保证题库导入幂等，重复导入不会产生重复题目。
- **user_answer 存 JSON**：单选 `["A"]`、多选 `["A","C"]`、填空 `["答案1","答案2"]`、判断 `["对"]`、主观题 `"作答文本"`。
- **exam_questions 冗余存 score**：便于组卷时不同题型赋予不同分值（如综合卷多选 2 分）。
- 计时以服务端 `deadline_at` 为准，防止客户端改时间作弊。

5. 同一文件内不重复考点；不同批次通过 ext_id 与题干去重。
6. 计算类题目必须数值可验证。

## 7. 组卷策略

### 7.1 上午卷（75 题单选，150 分钟，75 分）

按 2.2 表的分值分布抽题：

| 模块 | 抽题数 |
| --- | --- |
| DS_ALGO | 17 |
| SE | 14 |
| OO | 11 |
| DB | 10 |
| OS | 8 |
| NET | 6 |
| PL | 5 |
| CO | 2 |
| SEC | 1 |
| MULTI | 1 |

抽题算法：

1. 每个模块内按难度分层（易 40%、中 40%、难 20% 左右）随机抽取，模块间互不重复。
2. 同一次考试内题目按模块归并后再打乱（避免连续同模块出题，但保证全覆盖）。
3. 若某模块题量不足，则从相邻模块补足并提示（题库配额已保证充足，正常不会触发）。

### 7.2 下午卷（5 题主观，150 分钟，75 分）

| 题号 | 题型 | 分值 |
| --- | --- | --- |
| 1 | 数据流图 | 15 |
| 2 | 数据库设计 | 15 |
| 3 | UML 建模 | 15 |
| 4 | 算法设计 | 15 |
| 5 | 程序设计（C++ / Java，随机二选一） | 15 |

每题从对应考点池随机抽取，保证 5 题考点不重复。

### 7.3 综合训练卷（85 题，120 分钟，100 分）

| 题型 | 数量 | 每题分值 | 小计 |
| --- | --- | --- | --- |
| 单选 | 40 | 1 | 40 |
| 多选 | 15 | 2 | 30 |
| 填空 | 15 | 1 | 15 |
| 判断 | 15 | 1 | 15 |
| 合计 | 85 | | **100** |

各类题型均按模块权重分层抽取，确保覆盖 ≥ 8 个模块。

### 7.4 随机性

- 使用 `crypto.randomInt` 抽取，每次组卷结果不同。
- 记录用过题目无意义（题库 1000+，一次考试最多 85 题），因此不做跨场次去重；但同一场考试内绝不重复。

## 8. 评分规则

### 8.1 客观题

| 题型 | 规则 |
| --- | --- |
| 单选 | 与标准答案完全一致得满分，否则 0 |
| 多选 | **全对得满分；少选、多选、错选均不得分**（软考无多选，此规则沿用"全对才给分"的严格标准） |
| 判断 | 与标准答案一致得满分 |
| 填空 | 每个空分值 = 该题分值 / 空数；答案归一化后比较（去首尾空格、全角转半角、忽略大小写、忽略多余空格），支持 `|` 分隔的多个可接受答案 |

答案归一化细节：

```
输入 → trim → 全角字母数字转半角 → 去除所有空白 → 转小写
比较时：候选答案数组中的任意一个匹配即该空得分
```

### 8.2 主观题

- 自动评分阶段不计分，`awarded = NULL`。
- 交卷后展示标准答案与评分要点，用户按题自评（0–15 分，支持 0.5 分档）。
- 自评分数写入 `exam_questions.awarded` 并重算试卷 `subjective_score`、`total_score`。
- 历史记录展示主观题得分与是否已评。

### 8.3 合格判定

- 上午卷：总分 ≥ 45 合格（满分 75）。
- 下午卷：总分 ≥ 45 合格（满分 75）。
- 综合训练卷：≥ 60% 判定为"通过"（满分 100）。

## 9. 接口设计（API）

统一前缀 `/api`，请求/响应均为 JSON（UTF-8）。错误响应 `{ "error": "错误信息" }` + 4xx/5xx 状态码。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/meta` | 题库统计（各题型、各模块数量）、考试模式定义、当前是否有进行中的考试、局域网地址 |
| POST | `/api/exams` | 开始考试，body `{ "mode": "morning" }`；若已有进行中的考试返回 409 + 该考试信息 |
| GET | `/api/exams/:id` | 获取试卷（含作答状态、剩余秒数）；到期未交卷则服务端自动强制交卷 |
| PATCH | `/api/exams/:id/answers` | 保存单题作答，body `{ "seq": 3, "answer": ["B"] }` |
| POST | `/api/exams/:id/submit` | 交卷；存在未答题返回 422 + 未答题号数组 |
| POST | `/api/exams/:id/abort` | 放弃本次考试 |
| GET | `/api/exams/:id/result` | 交卷后成绩详情（逐题对错、标准答案、解析、主观题评分要点） |
| POST | `/api/exams/:id/grade-subjective` | 主观题自评，body `{ "scores": [{ "seq": 76, "score": 12 }] }` |
| GET | `/api/exams` | 历史记录列表 |
| DELETE | `/api/exams/:id` | 删除一条历史记录 |
| GET | `/api/health` | 健康检查（自测用） |

### 9.1 计时与强制交卷

- 试卷创建时写入 `deadline_at = started_at + duration_sec * 1000`。
- 任何读取试卷的请求都会检查 `now > deadline_at`，若是则执行强制交卷（`auto_submitted = 1`），返回 `status: "submitted"`。
- 客户端倒计时归零立即调用 `POST /submit`，服务端同样兜底。

### 9.2 单人约束

- 新开考试时若存在 `status = 'in_progress'` 且未过期的试卷，返回 409，前端提供「继续作答」与「放弃并重考」。

6. **移动端**：≥ 768 px 右侧答题卡常驻；< 768 px 顶栏简化，答题卡为底部抽屉，上一题/下一题固定底部。
7. **防误触**：交卷与离开页面提示。

## 6A. 历年真题导入（补充）

### 6A.1 来源与授权

- 来源：GitHub 公开仓库 `chenxuhl/medium-software-designer` 中《2022年11月软件设计师上午真题及答案解析.pdf》。
- 用途：个人备考练习，不对外分发；题目前标注“真题”来源与年份。
- 覆盖：2022 年下半年上午卷完整 75 题（题号 1–75），答案与 PDF 文末“参考答案”逐题比对，**75/75 一致**。

### 6A.2 处理流程

```
PDF → pdfjs-dist 提取文本（按坐标重排行）→ 版式解析（blank/inline）
    → 人工修正（上标/下标等 1 题）→ 模块分类（关键词规则）→ data/raw/real_2022下.json
    → 统一校验去重（真题优先）→ SQLite（paper / paper_title / source / seq_no 字段）
```

- 版式 A（blank）：题干 + “（N） A. …” 选项行，答案在文末“参考答案”，适用于 2022 下试卷。
- 版式 B（inline）：题干 + “A. …” 选项 + “参考答案：X”，适用于 2020 下试卷（解析未完全通过校验，暂未导入）。
- 多空题（同一题干对应两个空）在本题库中拆为两道题，共用题干、题干中保留（N）编号。

### 6A.3 接口与界面

- `GET /api/papers`：返回可用真题套（年份、题量）。
- `POST /api/exams` `{ mode: "real", paper: "2022下" }`：整卷模考。
- 首页新增「历年真题」区域，显示真题套与“开始真题模考”按钮。

### 6A.4 其他年份未导入的原因

| 年份 | 问题 |
| --- | --- |
| 2020 下 | 题号混排（多空题、解析内数字干扰），自动解析仅 54/75 通过，暂不导入 |
| 2021 上 / 2021 下 | PDF 中无答案文本（答案在答题卡图片/解析图片中） |
| 2023 上 / 2024 上 | PDF 为扫描图片，无可提取文本 |
| 2023 下 | 公开卷仅 1–60 题有文字解析，不完整 |

> 如需补充：提供文字版试卷或含答案的 PDF，执行 `node scripts/import-real.mjs <pdf> <paperId> <标题> [blank|inline]` 即可接入。

## 12. 自测方案

| 多选少选 / 多选 / 错选 | 0 |

## 12B. 练习模式与试卷重做

### 12B.1 练习模式

- 入口：首页「练习模式」两张卡片（基础知识 / 应用技术），路由 `#/practice/basic|application`。
- 抽题池：
  - 基础知识：`single / multi / fill / tf`（共 1945 题，含真题）；
  - 应用技术：`subjective`（210 题）。
- 循环规则：服务端为每个模式保存一份洗牌后的题目顺序（`settings.practice-order:<mode>`）；客户端用 `pos` 游标请求 `GET /api/practice/next?mode=&pos=`，一轮取完（pos ≥ 总数）时服务端重新洗牌开启下一轮，因此**同一轮内不会重复，全部循环后才会再次出现**。
- 幂等设计：位置由客户端游标决定，服务端不改变读取位置；网络重试不会跳过题目。
- 交互：作答后点「下一题」→ `POST /api/practice/check` 返回答案、解析（主观题返回参考答案与评分要点）并展示；按钮变为「继续下一题 →」，再次点击进入下一题。
- 前端用 `localStorage`（`practicePos:<mode>`）记住进度，刷新后继续。

### 12B.2 重做试卷

- 接口：`POST /api/exams/:id/retake`，复制原试卷的题目、顺序与分值，生成一场新考试（标题加「（重做）」）。
- 入口：成绩页「重做这套试卷」按钮、历史记录每条记录的「重做」按钮。
- 约束：若已有进行中的考试，返回 409，前端弹窗提供「继续上次考试 / 放弃并重做」。

## 12A. 部署在反向代理子路径（/exam/）

需要把考试系统挂在已有站点的子路径下（例如 `https://example.com/exam/`）时，用 Nginx 反向代理即可，无需改动代码：

```nginx
location /exam/ {
    proxy_pass http://127.0.0.1:8787/;   # 末尾斜杠：转发前去掉 /exam 前缀
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}
```

- 前端：静态资源与接口均使用**相对路径**（`PAGE_BASE`），因此同一套页面既能在 `/` 根路径运行，也能在 `/exam/` 子路径运行。
- 代理需保留原始方法、请求体与响应头，`PATCH` / `DELETE` 才能正常工作。
- 访问：`https://<你的域名>/exam/`。
